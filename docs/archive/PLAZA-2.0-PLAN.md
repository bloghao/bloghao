# 广场 2.0 提案：从「一条河」到逛得下去的广场（2026-10-16 立项）

> 站长立项语：让人们除了在自己的博客上、微博上写内容，也**愿意偶尔到广场上转转、看看**，
> 且能有效互动，**带动互相回访**，带动整个生态繁荣。
> 本文件是完整方案与推进步骤；ROADMAP 登记为 **B25**，各阶段启动后按需拆条目跟踪，落地细节回写 PLAZA.md。

## 一、V1 复盘：已有与短板

**已有（B17，2026-10-10 落地 + 2026-10-16 分站自动收录）**：hub 独立服务（`plaza/`，Workers/Node 双形态）承载站点注册、签名 push ingest、RSS+微博 pull 补漏、混排 feed（recency + weight + jitter）、管理端点与统计；官网 `/plaza/` 静态页单列流（全部/文章/微博页签 + 换一批 + 站点名录侧栏）；站端「广场同步」插件（发布实时 push、删除/锁文自动下架）；docker-poc 控制面开站即自动收录 + token 落库。

**对照「转转、看看、互动、回访」四个词的短板**：

1. **只有一个单列时间线**——是「读的流」不是「逛的场」。图片卡没有版面优势，刷三屏就腻；没有站点维度、话题维度的进入路径。
2. **零互动**——看完了只能走，连点赞都没有；内容好不好全靠混排运气，没有热度信号。
3. **零留存钩子**——没有关注、没有订阅、没有周期性内容，来一次是一次；站长也不知道广场给自己带没带来访客，没有回来的理由。
4. **话题维度缺失**——标签只存在于各站内部，广场聚不起来；「今天大家在写什么」这个问题广场答不了。
5. **新站冷启动只有曝光没有身份**——混排里新文有 recency 加权（这点是对的），但「新站是谁、靠不靠谱」没有呈现（名录里一行域名）。
6. **治理工具薄**——只有 hidden / disabled 两个开关，无举报入口、无滥用观测。

**不动摇的边界**：hub 是派生数据，只存标题/摘要/链接/封面，不收正文/评论/访客身份；**不建用户体系**（复杂度与隐私双重预算，互动一律轻量化）；互动数据是匿名聚合计数，不是行为档案；官网页保持 ES5 无构建；hub 保持零依赖、Workers（D1）/ Node（node:sqlite）双形态同构；**不伪造任何数据**（内容只来自 push/pull 两条路，互动计数只来自真实访客行为）。

## 二、设计总纲：三个循环

```
看 ──────→ 逛 ──────→ 动 ──────→ 回 ──────→ 再看
│           │           │           │
P1 排版升级   P1 站点/话题   P2 轻互动     P3 留存钩子
卡片墙双视图   维度进入路径   点赞+数据回流   关注/RSS/周刊
```

- **看 → 逛**：把「一条河」升级成「一个场」——卡片墙给图卡版面优势，站点视图和话题视图给「逛」的路径。
- **逛 → 动**：轻互动（匿名点赞）让访客能留下痕迹；曝光/点击回传让热度可量化。
- **动 → 回**：互动数据反哺站长（广场数据卡）、`utm_source` 让回访可观测、关注/订阅/周刊给所有人周期性回来的理由——**站长看到广场带量 → 愿意互访别人 → 内容更多 → 访客更有得逛**，生态正循环在这一环闭合。

## 三、分阶段推进

### P0 地基补强（小改动先行，1–2 天量级）——✅ 2026-10-16 落地（feed?site= / RSS 站名回填 / 图片降级+懒加载 / 新站聚光 +2 档与「新」标）

| # | 事项 | 说明 |
| --- | --- | --- |
| P0.1 | feed API 站点过滤 | `GET /api/feed?site=N`（站点视图数据面，SQL 已选 `s.id AS siteId`，加一个 WHERE 即可）；limit/kind 参数同口径 |
| P0.2 | pull 路站点名自动补全 | 首次 pull 时从 RSS channel `<title>` 回填 `site_name`（2026-10-16 实测缺口：docker 自动收录的 5 站因未设站点标题，名录里全是裸域名）；已有名字不覆盖 |
| P0.3 | 广场页图片降级 | 外链封面 `onerror` → 无图卡（今天图挂了就是破图，第三方站防盗链不可控）；懒加载 `loading="lazy"` |
| P0.4 | 新站聚光 | 混排评分里给 `created_at` 7 天内的站点 weight 临时 +2 档（hub 端一行，冷启动扶持）；聚光期在站点名录展示「新」标 |

### P1 看得舒服：广场页 2.0 排版（纯 website/ 前端 + P0 数据面，见效最快）——✅ 2026-10-16 落地（拍板采纳建议：桌面默认卡片墙、移动默认河流，偏好记 localStorage）

- **双视图**：「河流」（现状单列流，保底不删）+「卡片墙」（双列瀑布流，CSS `columns` 实现——ES5 无构建约束下零 JS 布局）；用户偏好记 localStorage。
- **卡片三型**：文章图卡（封面 16:9 裁切 + 标题 + 60 字摘要 + 站点头像/名）、微博卡（正文优先 + 配图）、文字卡（无图兜底，摘要加长到 120 字补版面）。
- **站点视图**：点站点名/头像进入该站视图（`/plaza/?site=N`，hash 或 query 均可，保持纯静态）——该站近期内容 + **「去逛逛 ↗」大按钮**（回访主入口）；页面顶部返回全场。
- **侧栏升级**：站点名录 → 近 7 日活跃榜（按条数）+「最新入驻」位（新站聚光的展示面）；`/api/sites` 出参补 `recentItems`（近 7 日条数）。
- **移动端**：<720px 单列（卡片墙退化为大卡流），390px 过老规矩。
- 拍板点：卡片墙是否默认视图（建议：桌面默认卡片墙、移动默认河流）。

### P2 逛得起来：轻互动与数据回流（需拍板后动工）——✅ 2026-10-16 落地（拍板点均按建议值执行：点赞每 IP 每条 1 次/天 + 每会话 60 次/天 + 每 IP 全场 200 次/天；曝光按（北京日，站点）两维聚合写 site_stats 表，无条目级/访客级记录）

- **P2.1 匿名点赞**：`items` 加 `likes` 计数列；广场页每卡一个点赞动作，无登录——防重走 vid 口径（localStorage 记已赞）+ hub 端按 IP 限流；卡片显示计数（≥1 才显示，零赞不渲染避免冷清感）。
- **P2.2 曝光/点击回传**：官网广场页把卡片曝光与出站点击**聚合成批量匿名计数**上报 hub（无 IP 无指纹，比站内 visit_log 更轻；攒 N 条或 30 秒合并一 POST）；hub 聚合 per-site CTR。
- **P2.3 站长数据卡**：hub 新公开端点 `GET /api/site-stats?token=<站点token>`（复用 ingest 同款 token 即身份口径，出参只含本站的曝光/点击/点赞/近 7 日趋势）；站端「插件 → 广场同步」设置卡展示——**站长看见广场带来的量，是回访广场最强的理由**。
- **P2.4 「来自广场」标记**：官网页渲染出站链接统一追加 `?utm_source=bloghao-plaza`（客户端拼参，hub 数据不动）；各站 visit_log 已记来源域名，站长在自己后台直接看到广场回访量。
- 拍板点：① 点赞限流与防刷口径（建议每 IP 每条 1 次/天、每会话 60 次/天）；② 曝光打点的写量级（按日聚合进 stats 表可承受，需 EXPLAIN 验证）。

### P3 留得住：关注 / 订阅 / 周刊

- **P3.1 本地关注**：站点卡「关注」→ localStorage 关注列表 → feed 顶部「我的关注」视图（纯客户端过滤已拉取的 feed，零服务端、零账号、零隐私争议）；关注列表导出为 OPML 是加分尾件。
- **P3.2 广场 RSS**：hub 输出全场 feed 的 RSS（`/api/feed.xml`，截 50 条、只含标题/摘要/链接）——**整个广场变成一个可订阅源**，用阅读器的人不打开网页也能「逛」；hub 双形态同构实现。
- **P3.3 周刊**：管理端「本周精选」标记（独立 picks 表或 items.featured 位）+ 官网「周刊」页签；半自动流水线——hub 先按曝光+点赞聚合出「本周热门 Top20」草稿，管理员勾选定稿；定稿形态拍板（官网动态页 vs 手工静态文，倾向前者数据面 + 静态页渲染）。
- 拍板点：周刊频率（周更起步）、是否同步 TG 频道推送（官方 TG 通知通道现成）。

### P4 话题与搜索（内容维度，复用 P1 卡片）

- **P4.1 tags 进协议**：ingest items 增可选 `tags`（≤5 个，hub 端清洗白名单）；RSS pull 解析 `<category>`；`items.tags` JSON 列 + `GET /api/topics` TopN。协议是**增量可选字段**，老站不带上报不受影响。
- **P4.2 话题页**：`/api/feed?tag=` + 官网 `#tag-xxx` 视图，复用卡片墙——「今天大家都在写什么」的答案页。
- **P4.3 广场搜索**：标题/摘要 LIKE 检索起步（hub 内容量级 ≤ 数万，LIKE 足够；FTS 双形态成本高不划算）；入口放卡片墙顶部。
- 依赖：P1 卡片墙先行（话题页就是过滤后的卡片墙）。

### P5 信任与治理（伴随放量持续）

- **P5.1 认证自动化并轨 B18**：token 验证文件 / DNS 校验自动签发 `verified`（与 2026-10-16 docker 自动收录同一信任模型的延伸——hub 管理员审站点→站点自证所有权）。
- **P5.2 举报入口**：卡片「举报」→ hub 举报表（匿名：目标条目 + 理由枚举 + IP 限流）→ 管理面处置（`items.hidden` 已有，补个处置入口）。
- **P5.3 pull-only 站下架自愈（研究项）**：未接插件的站删文后 hub 感知不到（pull 只增改不删）；评估「连续 N 次 pull 缺席即隐藏」的误伤率——RSS 只带最新 20 条，高产站 30 天内的老文会假性缺席，需结合 `published_at` 窗口判定，**先研究再动手**。
- **P5.4 滥用观测**：stats 趋势已有；补 ingest 异常告警（同 token 高频 / 超大 payload 聚合提醒）。
- **跨站评论互通（Webmention 式）**：**立项待研究，不进本计划排期**——把 UGC 从访客→hub→源站走双重审核链，复杂度、滥用面、源站审核负担都大；源站已有先审后展是兜底但不改变链路复杂度。单独拍板。

## 四、成功度量（怎么算「繁荣」）

- **供给侧**：接入站点数、周活跃站点（7 日内有新条目）、周新增条目数（/api/admin/stats 已有基础）。
- **消费侧**：feed_hits 7 日趋势（≈广场页访问）、人均浏览深度（P2.2 上线后有曝光/点击比）。
- **循环侧**：`utm_source=bloghao-plaza` 回流量（站长侧观测，官方侧可从点击计数交叉验证）、点赞率、关注使用率。
- 里程碑建议：接入 30 站 / 周新增条目 100+ / 广场页周 UV 翻倍，逐级触发 P3 / P4 提前。

## 五、归宿与工程纪律

- **P1** 纯 `website/` 前端；**P0 / P2 / P3 / P4** 主体在 `plaza/`（hub）+ `website/`（官网）+ 少量站端（插件数据卡挂在「广场同步」插件设置区）；**不动内核 `src/`**（协议扩展在 hub 端消化，站端只动 hooks.ts 插件与 api 公开口）。
- hub 每张新表/新列都要 Workers D1 与 Node hub-node 双形态同步（schema.sql 一处定义），管理面沿用 Bearer PLAZA_ADMIN_TOKEN 单管理员模型；公开 GET 才开 CORS。
- 官网页沿用 esc / ES5 / 无构建三纪律；移动端 390px 检查过老规矩。
- 每阶段落地后：PLAZA.md 更新协议与用法、tests/plaza-hub.test.ts 补纯函数用例、AGENTS.md 登记新防线。
