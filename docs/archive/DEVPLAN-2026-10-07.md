  `/api/public/rank`(走 SSR 的 RankData)、`/api/member/points`(有真实消费方再走契约变更)

## 契约现状速查(以代码为准,此处只列口径)

- 枚举:`minTier = all | member | coffee | top`(脏值归 all,宁漏勿锁死);`tier = normal | coffee | top`
- registry:`MemberData` / `RankData` / `MemberView` / `RankEntryView` 定义见
  `src/themes/registry.ts`;`member()` / `rank()` 是 ThemeModule 可选成员,缺省时 pages.ts
  兜底通用版——主题作者可只实现部分页面
- 会话:会员独立 Cookie `xw_member_session`,与管理员 `bloghao_session` 互不干扰
- 端点出参形状见 docs/API.md,不在本文重复:会员六端点(register/login/logout/me/profile/password)、
  后台 `GET/PUT /api/admin/members`(PUT 缺键即保留;列表出参剥 password_hash/salt,同
  postAdminView 口径)
- 个人资料(2026-10-07):昵称注册选填(中英文均可、仅展示不唯一、清洗与窗口判定纯函数在
  `utils.ts cleanNickname` / `nicknameCooldown`),**30 天一次**修改——窗口判定下沉 SQL 条件更新
  (`members.display_name_changed_at`,NULL = 从未改过首次不受限,防并发双开);改密码验证旧密码、
  成功后其他设备会话全失效(当前保留,`auth.ts destroyOtherMemberSessions`),无找回,表单旁固定提醒
- 评论头像(2026-10-07,C2):`POST /api/member/profile` 带 `qq` 键即绑定/重试(校验
  `utils.ts isValidQQ`,5-11 位数字 1 开头;抓 q1/q2.qlogo.cn s=140 → 魔数识别 → saveUpload
  站内转存 → 回写 members.avatar;**抓取失败容忍只存 qq**,重跑同一请求补抓,db 层 avatar
  COALESCE 不清已有头像);出参 `qq`/`avatarUrl`/`avatarFailed` 只进本人视角;**qq 号本体
  任何公开出参不携带**(评论/榜单/会员公开视图一律不出),头像一律站内 /images/ 转存后同源
  输出——直接拼 qlogo 外链会暴露用户 QQ 号,不取;评论头像位游客与未绑会员退回昵称首字块
  (`render.ts commentAvatarHtml`,site.js 微博评论渲染是 ES5 手工镜像)
- 游客 QQ 头像(2026-10-07 拍板,原「待拍板」项):评论三路表单可选填 `qq`(仅游客表单出该框,
  会员/作者身份发言不带);服务端校验 `isValidQQ`,**格式不对按没填处理**(选填字段不拦评论),
  合法则先查同号历史头像直接复用(抓取次数 = 唯一 QQ 数,且被评论限流再压一层),未命中才走
  fetchQQAvatar 抓取转存;落 comments.qq(内部列,任何公开出参不携带)+ comments.avatar(站内
  /images/ 地址,公开);头像位取值优先级 会员 member_avatar → 作者 adminAvatar → 游客 avatar
  → 昵称首字块
- settings:`membersEnabled`('1'/'0' 默认 '0';关 = /member、/rank 一律 404,已锁文章仍按
  minTier 生效)、`rankTopN`(1–50 默认 '10')

  member_sessions / member_points_log 三表(临时凭证表不进备份);members.display_name_changed_at
