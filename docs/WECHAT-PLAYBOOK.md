# 「微信同款」参考手记（WECHAT-PLAYBOOK）

> **这是内部参考报告，不是路线图、不是承诺。** 它回答一个问题：
> **「如果让这个博客在**使用逻辑**与**视觉手感**上更接近微信，能做到什么程度、代价是什么、哪些能做哪些做不了？」**
>
> - 配套：`AGENTS.md`「全站移动端适配」是**红线**，`docs/MOBILE-UX.md` 是**操作手册**，本页是**素材与判断**。
> - 与本页相关的既有规划：`docs/ROADMAP.md` 的 **C10（PWA）/ C11（阅读偏好）/ B3（通知渠道）/ B15（支付）**——本页不重排编号，只把它们放到「微信坐标系」里重新解释一遍。
> - 涉及微信开放平台能力的部分，**门槛都写实**（认证、IP 白名单、JS 安全域名）。做不了就明说，不画饼。

---

## 0. 结论先放这里（TL;DR）

1. **「像微信」要分三层看**——**手感**（可抄，零门槛）、**形态**（部分可抄，客户端能做）、**生态**（抄不了也不该抄，那是围墙）。
2. 本项目**已经是一半的微信**：wechat 主题（默认）、微信排版规范与编辑器体检、微信表情文本码（93 个）、九宫格 / 话题 / 视频、封面缩略图列表、评论先审后展、阅读进度条、分享卡（含二维码）。**缺的不是「功能」，是「手感的一致性」**——微信的味道来自每个反馈都**即时、克制、无惊喜**，这一条比任何单个功能都值钱。
3. **最高性价比的三件事**（纯客户端、零门槛、感知最强）：① **读者侧字号调节 + 记忆**（微信公众号「调整字体」同款，对应 C11）；② **右上角「…」聚合菜单**（把分享 / 复制链接 / 字号收进一个从底部升起的半屏面板 = 微信每个页面的手势直觉）；③ **图片查看器对齐微信手势**（双击缩放、下拉关闭、长按菜单，在现有 lightbox 上补齐）。**——①②③ 已于 2026-10-17 落地（纯 `site.js`，零内核改动），见 §9。**
4. **能做得像但需要「新表 / 新抽象」的，先一律降级成客户端方案**：划线 / 想法、收藏 / 阅读清单，**先用 `localStorage` 做**，别一上来进内核（见 §9、§11）。
5. **微信开放平台能力（公众号草稿箱 / JS-SDK 分享 / 网页授权 / 模板消息）全部需要「已认证的服务号」+ IP 白名单 / JS 安全域名**——个人订阅号做不了。**只能作为「可选插件 + 失败静默退化」，永远不能进核心链路**，否则等于给整个系统绑一个封号就瘫痪的外部依赖（违反复杂度预算与「无构建链」的轻定位）。
6. **最该拒绝的**：微信的**封闭性**（登录墙、无外链、无 RSS、无 SEO）。本项目是**开放博客**——要抄的是它的**克制与顺手**，不是它的**围墙**。这一条是红线，见 §8。

## 2. 微信的设计语言拆解（「味道」从哪来）

想把「微信感」搬过来，得先把它拆成可执行的清单。下面每一条都标了**能不能抄**。

### 2.1 色彩与材质

- **品牌绿 `#07C160`**（流程主色）、**微信红 `#FA5151`**（危险 / 未读）、**朋友圈橙 `#FA9D3B`**（次要强调）。
- **灰阶层级**：背景 `#EDEDED`、卡片 `#FFFFFF`、分隔线 `#EDEDED`、次要文字 `#888888` / `#B2B2B2`；深色模式背景 `#191919`、卡片 `#1F1F1F`。
- **材质克制**：几乎**不用阴影**，用**分隔线 + 灰阶**表达层级；卡片圆角统一（微信 8.0 后约 **8px**）。
- 本项目映射：wechat 主题已按这套色板走；「外观变量」(`src/appearance.ts`) 已把**主色 / 正文 / 次要 / 背景 / 卡片 / 分隔线 / 链接**七个角色抽成旋钮，**圆角 `--p-radius`** 也已是 token（默认值可查 `THEME_APPEARANCE` 表）。

> **可抄指数：★★★★★**（已经抄了）。新增 UI 一律用主题变量的七个角色 + `--p-radius`，**不要写死颜色和圆角**——这是「全局像不像微信」的根。

### 2.2 布局与导航

- **顶栏 44px**，左「返回」、中标题、右「…」；**「…」永远是「聚合菜单」**，不是一堆并列图标。
- **底部标签栏 4–5 项**，高频在栏、低频进「更多」；选中态用主色。
- **无汉堡菜单**（微信不用侧滑抽屉做主导航）。

> **可抄指数：★★★★☆**。后台已有底栏 + 「更多」抽屉，**方向正确**；差的是一致性（见 §7）。
> 前台读者页**不建议**加底栏——博客信息架构比 App 扁平，加底栏是**负重**而非减负。前台只借「右上角 … 聚合菜单」一条（见 §4.4）。

### 2.3 动效与反馈（**微信味道的真正来源**）

- **转场极快**（约 250–300ms，`cubic-bezier` 类似 `ease-out`），**几乎无回弹**；微信的「高级感」来自**快、干净、不打折**，不是华丽。
- **即时反馈**：点按有 `:active` 轻微压暗 / 缩放（约 `0.97`）；操作成功用**居中黑底圆角 Toast**（约 1.5s 自动消失）。
- **危险操作**：**二次确认对话框**（居中圆角卡，左「取消」右红字「删除」）。
- **列表手势**：左滑露出操作（删除 / 置顶 / 标为已读）；**长按**弹操作浮层。
- **半屏面板**：操作面板从**底部升起**（分享 / 选择），点遮罩消失。
- **可动效要能被关掉**：本项目已尊重 `prefers-reduced-motion`（site.js 里在用）。

> **可抄指数：★★★★★**（纯客户端，WKWebView / 现代浏览器全支持，ES5 也能写）。
> **这是本页最推荐的投入方向**：不新增一个功能，只把「每个点击都有即时、克制、可预期的手感」补齐。

### 2.4 文字与信息密度

- 正文 **17px / 行高约 1.6**（iOS 微信），标题层级用字号 + 灰阶，不用花体。
- **能折叠就折叠**：朋友圈长文折叠成「全文」；列表摘要 1–2 行截断（`-webkit-line-clamp`）。
- **时间戳弱化**（小灰字），**数字用 `tabular-nums`** 防跳动。

> **可抄指数：★★★★★**。本项目已遵守（`wechat-typography-spec.md`）；新增列表卡继续沿用。

### 2.5 微信**不能**抄的部分（红线，提前说清）

- **封闭**：登录墙、禁外链（要跳「即将离开微信」中间页）、无 RSS、无 sitemap、无 SEO。
  → 本项目**反着来**：`/go` 外链中间页是「**提醒但不拦**」、`outlink.ts` 白名单直跳、RSS / sitemap / JSON-LD 全开。**这是产品定位，不是待补的短板。**
- **中心化账号**：微信要手机号 + 实名 + 风控。
  → 本项目会员**可选**、评论可匿名、先审后展。
- **重运营**：模板消息、客服消息、图文群发都有配额与审核。
  → 本项目无配额概念，通知走可选 hook（TG / Webhook），失败吞掉不影响主流程。

## 3. 「读」（读者侧阅读体验）

### 3.1 已有：进度条 / 目录 / 吸顶导航 / 灯箱 / 代码复制 / 返回顶部

（细节见 `docs/MOBILE-UX.md` §1。）**这一层已经相当接近微信读书的「清爽」**，不建议推倒。

> **2026-10-17 补齐**：灯箱手势已对齐微信图片查看器——**下拉关闭**（够远且纵向为主）+ **长按菜单**（「保存图片 / 复制图片地址」，复用同一个底部面板组件），并抑制系统长按 callout（`-webkit-touch-callout:none`）让自家长按菜单接管。

### 3.2 缺口 A：读者侧**字号调节 + 记忆**（小程序 / 公众号「调整字体」同款）——✅ 已落地（2026-10-17）

- 微信在哪：公众号文章右上「…」→ **调整字体**（A- / A / A+）；微信读书「Aa」面板。
- **本项目落地形态**（纯 `site.js` 注入，归宿第 ① 档，零内核改动）：
  - 入口在正文页右上角「…」面板里的「字号」行：**小 0.9 / 标准 1 / 大 1.15 / 特大 1.3** 四档（待拍板里「3 档还是 5 档」按四档拍）。
  - **缩放走 `zoom`**（`CSS.supports('zoom', …)` 探测，不支持则降级为只缩放正文容器字号）：一次覆盖标题 / 正文 / 代码 / 表格，**无需七主题各改一段字号**——这是刻意避开「七主题同改」的做法，省下的是维护面。
  - **只作用于 `.rich` 正文容器**（列表页 / 微博页无 `.rich`，不启用、也不注入「…」入口）；不影响微博流正文。
  - 记忆走 `storeGet/storeSet`（键 `xw:reader:fs:v1`，红线：禁裸 `localStorage`）；默认档 `1`（不改动未设置读者的正文大小）。
- 对应：ROADMAP **C11**（其余 C11 子项如夜间开关见 §3.3）。
- 回归守护：`tests/reader-ui.test.ts`（档位表 / 标签表一致、倍率递增、默认档在范围内、记忆键经 `storeGet/storeSet`、面板不锁 body 滚动、无 lookbehind 正则）。

### 3.3 缺口 B：**手动夜间 / 护眼开关**（微信「深色模式」的简化版）

- **重要前提**：`wechat.css` 顶部**明确写着站长偏好「保持明亮、已关闭自动暗色」**。所以**不要**擅自加 `@media (prefers-color-scheme: dark)` 自动跟随系统——那会违背已有拍板。
- 建议形态：**读者侧可选开关**（默认关、跟随当前主题明亮），开启时给 `<html>` 加 `data-reader-theme="dark"`，由主题 CSS 提供一组覆盖（**跟系统解耦**——这样既尊重站长偏好，又给读者自主权）。
- 代价：中（每个主题都要认真调一套深色覆盖，否则「半黑」更难看）。**建议先只在 wechat 主题落地**，跑通再谈其他主题。
- 对应：ROADMAP **C11**。

### 3.4 缺口 C：**划线 / 想法（微信读书）**

- 微信在哪：微信读书**长按选中 → 划线 → 写想法 → 想法以「点 + 头像」贴在段落右侧**，他人想法可见。
- 本项目现状：无。
- **诚实评估**：这是个**真功能**（不是皮肤），一旦要做就涉及「划线数据存哪、是否可见、是否社交」。**这是本页里最需要克制的一条**：
  - **疑似过度**：为它新增表 + 公开面 + 审核，等于给「轻写作博客」加一个「社交阅读平台」的重量（违反复杂度预算）。
  - **轻量替代（推荐先试）**：**纯客户端「本地划线」**——选中文字后浮出「高亮 / 复制」小气泡（微信长按菜单同款手感），高亮存 `localStorage`（按文章 slug + 段落锚定），**只有自己看得见、换设备即失**。零新表、零公开面、零审核。
  - 真要做「可见的想法」（社交），应作为**独立提案**（涉及新表 / 新查询 / 防泄漏 / 审核），进内核前按归宿三档论证，别顺手做。
- 对应：**无 ROADMAP 编号**（本页新提），建议先在 `MOBILE-UX.md` Backlog 挂「本地划线」候选。

### 3.5 缺口 D：**阅读清单 / 收藏 / 浮窗**

- 微信在哪：聊天 / 文章**浮窗**、**收藏**、微信读书书架。
- 建议形态：**缓存优先**——「收藏」按钮存 `localStorage`（slug 列表），文章页顶部显示「已收藏」；**不做账号级收藏**（那是会员体系的事，别混进来）。
- 代价：低（纯客户端）。

### 3.6 缺口 E：**段落级分享 / 引用**

- 微信在哪：长按文本「引用 / 转发 / 搜一搜」。
- 建议：选中文字后浮层加「复制引用」（`> 原文片段` + 链接），**纯客户端**。

## 4. 「写」（创作与发布）

### 4.1 已有：MD 模式 / 微信表情 / 采集公众号 / 排版体检 / 锁文 / 定时 / MCP

（细节见 `AGENTS.md` 各防线节。）**写作侧已经很强，本页不主张大改。**

### 4.2 缺口 A：**「博客 → 公众号草稿箱」插件**（反向的公众号采集）

- 思路：文章写完后，一键推一份**公众号草稿**（`cgi-bin/draft/add`），排版沿用站内的公众号规范——**这是本项目最自然的微信联动**（已经解决了「反向采集」，正反向闭环）。
- **门槛必须写实**（做不到就别立项）：
  - **需要已认证的公众号 / 服务号**；个人订阅号**没有**草稿箱 / 发布接口权限。
  - **服务器 IP 白名单**：获取 `access_token` 要求调用方 IP 在白名单内——**Cloudflare Workers 出口 IP 不固定**，这是**硬伤**：线上主站（CF 托管）**直接做不了**，只有自托管 `docker-poc`（固定 VPS IP）形态可行。
  - 素材里**图文消息的图片必须传微信素材库**（`media/upload`），即正文图片要再转存一遍（公众号不允许外链图片）。
- 结论：**只可能作为「自托管形态的可选服务端插件」**，且必须**失败静默、绝不进核心链路**。对 CF 主站用户这一条**基本无用**——立项前先确认目标用户形态。
- 对应：**无编号**，登记为「待拍板」（§10）。

### 4.3 缺口 B：**微信风格编辑手感**（纯客户端）

- 长按选中 → 浮出「加粗 / 高亮 / 引用」快捷条（微信长按菜单的手感）；
- 输入即时排版（已有 A6/MD 模式，可复用）；
- **不做**微信那种「群发 / 定时群发」的运营面板——本项目已有定时发布，够了。

### 4.4 缺口 C：**读者页右上角「…」聚合菜单**（跨读写两面的一个手势）——✅ 已落地（2026-10-17）

- 微信在哪：**每个**内容页右上角都是「…」，点开半屏面板：分享 / 收藏 / 复制链接 / 调整字体 / 举报 / 刷新。
- **本项目落地形态**（纯 `site.js`，复用一套通用底部面板 `xwOpenSheet`）：正文页（有 `.rich`）**右上角「…」**在**导航滚出视野后**浮现（窄屏 ≤900px），点开底部升起半屏 `action sheet`，聚合：**分享 / 复制链接 / 字号（§3.2）**。
  - 分享**复用现有文章分享卡**（`.share-btn` 触发，含二维码 / 系统分享），无分享按钮的页面（关于我 / 独立页）退化为系统分享或复制链接。
  - 面板配色中性白 / 深（微信 action sheet 同款），**按主题底色亮度自动选深浅**（`getComputedStyle` 算亮度），因此不依赖各主题变量名、也不改七主题样式；`data-dark` 由运行时判定。
  - **位置取舍**：微信的「…」在顶栏，但本项目七主题顶栏形态不一（wechat 吸顶导航会挤），故做成**右上角浮起**（导航收起后出现，不与导航打架）——手感一致、零主题改动。
  - **精简口径**：「返回顶部」已有独立按钮、**不再进面板**（避免同一动作两个入口，见 `MOBILE-UX.md` §5）；「收藏」待第二批本地收藏落地后再并入。
- **这是「最像微信的一招」**：统一入口 + 收纳低频动作的地方。

## 5. 「连」（互动与运营）

### 5.1 已有：评论（先审）/ 点赞 / 微博 / 会员 / 排行榜 / 广场同步

### 5.2 缺口 A：**通知渠道多元化**（微信「服务通知」的位置）

- 微信在哪：公众号**模板消息 / 订阅通知**（服务通知里提醒「你的留言被精选」）。
- 本项目：通知走 **TG**（可选 hook），有 `onCommentCreated` 等事件。
- 建议：**保持现状方向**——本项目是开放博客，不该绑死微信生态；对应 ROADMAP **B3（通知渠道）**，加 **Bark / Server 酱 / 企业微信机器人** 比加「微信模板消息」更符合自托管用户（模板消息又需要认证 + 用户关注你的公众号，门槛极高）。
- 可做的小事：**Webhook 出站已有**（`outbound-webhook` 官方插件），**通知类需求优先接它**，不必新增内核。

### 5.3 缺口 B：**留言「精选 / 置顶 / 回复」**（公众号留言后台同款）

- 微信在哪：公众号留言**只显示被精选的**，作者可精选 / 置顶 / 回复。
- 本项目：**先审后展**（已有「精选」语义）、作者可回复、**后台可拉黑会员**。
- 可补：留言**置顶** + 「作者精选」标记（渲染层加个 badge）。**低成本**，但要注意「先审后展」是默认关还是开——别破坏现有默认。

### 5.4 缺口 C：**朋友圈「仅三天可见」思路 / 内容分级**

- 微信在哪：朋友圈三天可见、公众号「部分可见」。
- 本项目：已有 **会员付费墙（`min_tier`）+ 文章访问密码**——**语义已经覆盖**（付费墙 ≈ 分级可见）。**不建议**再引入「时间维度可见性」——那是新的门控维度，会让人困惑（线上内容突然消失对 SEO / 读者都是伤害）。

### 5.5 缺口 D：**打赏 / 赞赏**（公众号赞赏同款）

- 微信在哪：文末「赞赏」按钮（需开通原创声明 + 赞赏）。
- 本项目：ROADMAP **B15（会员 P2：支付 / 打赏）**——**已规划**，属商业功能，按 B 序列走，本页不重复。

## 7. 「后台像 App」（§4 of MOBILE-UX 的展开）

现状：底栏 `MOBILE_TAB_IDS = ['home','editor','posts','comments']` + 「更多」抽屉 + 红点 + Toast。
**方向对了，缺的是「微信那套统一手感」**。逐条对齐（**全在客户端**）：

| 微信习惯 | 后台现状 | 目标 |
| --- | --- | --- |
| 点按 `:active` 压暗 | 部分有 | 所有可点元素统一 `:active` |
| 列表左滑操作 | 无 | 评论 / 文章列表左滑「通过 / 删除」 |
| 长按弹操作 | 无 | 卡片长按弹浮层 |
| 底部升起半屏面板 | 弹窗是居中 `modal()` | 移动端动作面板改底部升起（`modal()` 加 variant） |
| Toast | 有 | 统一位置 / 时长 / 层级 |
| 二次确认 | 有 | 统一文案与危险色 |
| 骨架 / 菊花 | 不一 | 列表与详情统一 loading 态 |
| 下拉刷新 | 无 | 列表页顶部下拉刷新 |
| 震动反馈 | 无 | `navigator.vibrate`（可选，注意降级） |
| 顶部搜索常驻 | 不一 | 高频列表页搜索固定顶部 |

> **红线仍在**：后台新入口必须同时登记 `MENU` / `navigate()` / `MOBILE_TAB_IDS`；无内联事件属性；覆盖层有明确关闭键 + `env(safe-area-inset-bottom)`。

## 8. 红线与取舍（**最该先读的一节**）

1. **抄手感，不抄围墙。** 开放（RSS / sitemap / 外链中间页 / SEO / 匿名评论）是本项目的产品定位与用户价值，**任何「像微信」的改动都不能以牺牲开放性为代价**。
2. **不引入「封号即瘫痪」的外部依赖。** 微信开放平台能力（草稿箱 / JS-SDK / 授权 / 模板消息）**只能作为可选插件**，且必须**失败静默退化**；核心链路（写作 / 阅读 / 评论 / 发布）**永不依赖**任何需要认证的外部账号。
3. **客户端优先（归宿第 ① 档）。** 凡是能只用 `site.js` / 后台原生 JS 解决的，**不许动 `src/`**——「无构建链 + 一个下午读得完」是产品定位。
4. **不新增「公开面 / 设置键 / 数据表」除非过了归宿三档论证。** 划线 / 想法、微信登录、社交阅读都是这类高危项，**先做客户端轻量版验证价值**。
5. **ES5 / 禁 lookbehind / 禁裸 `localStorage`**：前台 `site.js` 一处解析错全站瘫痪，移动端最脆（红线，见 `MOBILE-UX.md` §2）。
6. **不破坏已有拍板**：深色模式「站长偏好明亮」、评论「先审后展」、外链「提醒不拦」、主题「皮肤包承接个性化」——动之前先问，别顺手改。
7. **精简是目标，不是副作用**：新东西若不能替换掉至少一个旧入口，就**默认不做**（`MOBILE-UX.md` §5）。

## 10. 待拍板问题（请站长定）

1. **读者字号调节**：3 档还是 5 档？只作用正文，还是也影响微博流？——**本轮按「4 档（小/标准/大/特大）、只作用 `.rich` 正文」落地**（推特档 / 加档位 / 扩到微博流都容易，说一声即可改）。
2. **夜间模式**：是否给读者侧开关（默认关）？只做 wechat，还是七主题都做？
3. **「…」聚合菜单**：前台是否接受新增一个右上角入口？——**本轮已按「窄屏 + 导航滚出视野后浮现的右上角浮起入口」落地**（不与吸顶导航打架、零主题改动）；若希望常显或移到底部，可调整。
4. **划线 / 想法**：只做「本地划线」（零新表）就够，还是要「可见的想法」（社交，需独立提案）？
5. **PWA（C10）**：值不值得为「后台添加到主屏」引入 service worker 的复杂度？
6. **公众号草稿箱插件**：目标用户是否包含「自托管 + 认证公众号」的人？若否，直接搁置。
7. **后台手势**（左滑 / 长按 / 下拉刷新）：优先级排在前台阅读增强之前，还是之后？
