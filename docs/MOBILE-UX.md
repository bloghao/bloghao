# 移动端体验与「精简」约定（MOBILE-UX）

> **这份文档是 AGENTS.md「全站移动端适配（长期约定）」的展开与操作手册。**
> AGENTS.md 那一节是**红线**（违反了就是 bug）；这一页是**手册**（目标、清单、评审口径、候选待办）。
> 新会话开工前读 AGENTS.md；**做任何 UI 改动前额外读这一页**。

## 0. 两个产品目标（写死，别漂移）

1. **手机是主场景，不只是「能看」**：读者在手机上读得舒服（长文、图片、评论、分享），站长在手机上**能写、能管**。移动端写作是硬要求，不是加分项。
2. **后台要「像 App」，不只是「响应式的网页」**：管理员登录后台，观感与操作手感接近一个原生 App（底栏、抽屉、手势、过渡、反馈），而不是把电脑版挤窄。
3. **够用就好、克制优先**：功能与信息架构尽量精简；能不加就不加，能藏就不摊开，能客户端解决就不烦服务端（见 §5「精简」原则）。

> 一句话取舍：**对外（读者）要「顺」，对内（站长）要「快」，对代码要「少」。**

## 1. 现状盘点（已有能力，改之前先确认别重造）

**前台（读者）**
- 七套主题全部响应式；wechat（默认主题）断点 `560 / 480px`，全站吸顶导航（`data-xw-nav-sticky`，下滚收起 / 上滑浮现）、正文标题锚点 + 桌面目录、七主题着色的**阅读进度条**（site.js 注入 `.xw-readbar-fill`）。
- **图片灯箱**（site.js：捏合缩放 / 拖动平移 / 左右切换 / **下拉关闭** / **长按「保存图片 / 复制图片地址」** / Esc 关闭）、代码块一键复制、长文滚动后「返回顶部」。
- **读者侧正文缩放 + 「…」聚合菜单**（site.js 注入，见 `WECHAT-PLAYBOOK.md` §3.2）：正文页（有 `.rich` 的页）右上角「…」在导航滚出视野后浮现，点开底部操作面板（分享 / 复制链接 / 字号 小·标准·大·特大）；字号走 `zoom` 缩放正文容器（一次覆盖标题 / 正文 / 代码 / 表格，不逐主题改字号），记忆走 `storeGet/storeSet`（键 `xw:reader:fs:v1`）。
- 评论 / 微博卡片在 `480px` 下重排；输入框聚焦字号 `16px`（防 iOS 放大）；文章页底部留 `env(safe-area-inset-bottom)`；深链定位高亮（`/weibo?wb=x#wb-x` 的 `:target`）。
- 分享：`navigator.share` 唤起系统面板 / 保存图片 / 复制图片（分享卡由 `share-card.js` 按需加载，含二维码）。
- 微信表情面板、微博九宫格 / 视频。

**后台（站长）**
- 移动端**底部固定标签栏**（`MOBILE_TAB_IDS = ['home','editor','posts','comments']`，见 `public/admin/app.js`）+「更多」抽屉（其余入口），栏外待审数聚合成红点（`.tab-dot`）。
- 写作编辑器顶栏两行、工具栏横滑；弹窗统一走 `modal()`（Esc / 焦点管理）；侧栏（桌面）可收起并记忆。
- 所有请求走 `api()`，401 统一回登录页；写操作 try/catch + toast + disabled 防连击。

## 2. 硬规则（红线，摘自 AGENTS.md，违反即 bug）

- 新增样式**至少验证 390px**；断点沿用：前台 `560 / 480px`，后台 `860 / 700px`。
- 输入控件（`input/textarea/select`）聚焦态字号 **≥16px**，否则 iOS Safari 自动放大页面。
- 底部固定栏 / 底部导航必须处理 `env(safe-area-inset-bottom)`。
- 视口 meta 保持 `viewport-fit=cover, interactive-widget=resizes-content`。
- 宽内容（表格、`pre`）小屏用 `overflow-x: auto`，不撑破容器。
- 覆盖层（抽屉、弹窗）小屏要有明确关闭按钮，且**默认不挡内容**。
- 导航 / 页头类布局改动必须过**「配置变体」四口径**：会员开/关 × 站点模式四态（本地默认库会员是关的，**开着会员导航会多一格会员药丸**——2026-10-11 实抓过它把 RSS 图标挤成孤儿行）。
- 前台 `site.js` 保持 **ES5**、禁 lookbehind、禁裸 `localStorage`（走 `storeGet/storeSet`）——**一处解析错误全站交互瘫痪**，移动端最脆。

## 3. 逐面检查清单（改完逐条过）

**前台 · 首页 / 列表**
- 390px 下刊头 / 搜索框 / 排序条 / 列表卡 / 翻页不溢出、不挤压；封面缩略图有固定尺寸不跳版。
- 顶栏导航：会员开/关 + 四种站点模式都过；单行横滑时下拉菜单不被 `overflow` 裁剪（wechat 已处理，新主题照抄口径）。

**前台 · 文章页（阅读主场景）**
- 正文行高 ≥ 字号；表格 / 代码块横向滚动；图片点击进灯箱；`prefers-color-scheme` 与主题口径一致。
- 评论表单：移动端键盘弹起时提交按钮可见；输入框 16px。
- 分享按钮：手机上能唤起系统分享（`navigator.share`），桌面端退化为保存图片。

**前台 · 微博 / 会员 / 结算类页**
- 九宫格 / 视频在窄屏的占比与限高（`.wb-video.is-portrait` 已有）；
- 会员登录 / 注册 / 改资料表单在小屏单列、按钮全宽、不出现横向滚动。

**后台 · 列表 / 表单**
- 表格类在大屏是表、小屏是卡（或横向滚动）；筛选 / 搜索控件不挤成一行「乱码」。
- 每个写操作按钮：请求期 `disabled`，成功 / 失败都有 `toast`。

**后台 · 编辑器（硬要求）**
- 手机能：贴图 / 传图 / 选附件（走 `pickFiles` 助手，否则 iOS 选完不回填）、存草稿、发布、预览、切 Markdown、开信息抽屉、跑体检。
- 工具栏横滑可及；信息抽屉小屏是从底部 / 侧边滑入的整屏抽屉，有 ×。

**后台 · 覆盖层 / 抽屉 / 弹窗**
- 有明确关闭键；点遮罩可关；打开时不锁死页面滚动导致卡死；`env(safe-area-inset-bottom)` 留白。

## 4. 「像 App」的目标态（后台为主，逐步逼近）

以下不是「必须一次做完」，而是**方向清单**——新增后台交互时优先从这里选，而不是发明新形态：

- **底部标签栏 + 更多抽屉**：已有。继续遵循「高频进底栏、低频进抽屉」的信息架构原则。
- **手势**：列表项左滑露出「通过 / 删除」等操作（微信聊天列表左滑的直觉）；卡片长按弹操作浮层。
- **过渡与反馈**：页面切换 / 抽屉 / 弹窗有轻过渡；危险操作（删除、清空）二次确认；成功 / 失败有 toast 与轻微震动（`navigator.vibrate` 可选，注意降级）。
- **加载态**：列表 / 详情用骨架屏或明确的 loading；请求失败给「重试」，别留白。
- **下拉刷新**（可选）：列表页顶部下拉刷新，符合手机直觉。
- **顶部搜索常驻**：高频列表页把搜索固定在顶部，滚动不跑。
- **可安装（PWA）**：manifest + 轻量 service worker 让后台可「添加到主屏幕」，获得全屏与离线壳（属 C10，需评估复杂度预算后单独立项）。

> 注意：以上都属**客户端能力**（归宿三档第 ① 档），优先写进 `public/admin/app.js` / `admin.css`，**不要为它们动内核**。

## 5. 「精简」原则（克制优先，产品定位的一部分）

「无构建链、一个下午能通读」是产品定位（见 AGENTS.md「复杂度预算」）。所以除了「不乱加」，还要**主动做减法**：

**该砍 / 该收的**
- **同一件事只留一个入口**：能合并的页面 / 按钮就合并（先例：「分类」并入文章页、设置页 11 个面板收进四页签）。
- **默认关、需要才开**：会带来配置负担或安全 / 隐私成本的功能默认关闭（会员、IP 属地、评论先审、各种外呼插件）。
- **能藏就不摊开**：低频项进折叠菜单 / 「更多」抽屉 / 设置内层，别铺在首屏。
- **能客户端就不进内核**：前台交互、阅读增强优先 `site.js` / 后台原生 JS（归宿三档第 ① 档）。
- **能用现成积木就不新增**：评论共性走 `publicComment`、卡片走 `render.ts` 公共件、样式走主题变量。

**该留的（底线，别为了精简砍掉）**
- 移动端写作能力、可访问性（alt / 对比度）、安全防线（净化 / 限流 / 防泄漏）。
- 二次确认 + 回收站 + 备份：**精简的是「入口与视觉」，不是「后悔药」。**

**判断口径（新增功能前自问）**
1. 它是不是**一个新的公开面 / 一个新的设置键 / 一个新表**？是 → 先按归宿三档找更轻的形态。
2. 它能不能**只改客户端**？能 → 就别碰 `src/`。
3. 它会不会**只在一种配置下正确**（如只在会员关时好看）？会 → 先过 §2 的四口径。
4. 删掉它，**核心体验（读 / 写）**会不会受损？不会 → 默认不做。

## 6. 新增 UI 的评审清单（收工前逐条勾）

- [ ] 390px 实机 / 模拟器过一遍（前台 + 后台，含编辑器）。
- [ ] 四口径：会员开/关 × 站点模式四态。
- [ ] 输入框聚焦 16px、底部安全区、宽内容横滚、覆盖层有关闭键。
- [ ] 触控目标 ≥ 44px 见方（主要按钮 / 链接）。
- [ ] 前台是否仍然**无新增单点解析失败**（site.js ES5 / 禁 lookbehind / 禁裸 localStorage）。
- [ ] 有没有**新入口**？有 → 是否需要同时登记 `MENU` / `navigate()` / `MOBILE_TAB_IDS`（后台约定）。
- [ ] 这次改动能不能**只留在客户端**？如果能却动了内核，回退重想。
